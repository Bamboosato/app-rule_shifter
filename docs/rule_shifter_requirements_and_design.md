本ドキュメントは、臨床神経心理学における前頭葉機能評価の金字塔「ウィスコンシン・カード分類課題（Wisconsin Card Sorting Test: WCST）」の思考実験を一筆書き迷路探索ゲームへと昇華させた脳トレWebアプリケーション『Rule Shifter（ルール・シフター / 潜伏規則迷路）』を、商用・本番水準のWebアプリケーションとして開発・実装するための詳細な要件定義書および基本・詳細設計書である。

『Stroop Route』で検証・確立された**UI/UX設計思想（Container Query `100cqw` によるセルサイズ完全均一化、等幅巨大数字 `tabular-nums`、ネオングロー高コントラスト、4×4ファインダースライディング）**を完全継承し、さらに「完全ブラックボックスの潜伏ルール推理」「アブダクション（仮説形成）」「サイレント相転移（ルールの突然変異）」「保続エラーの抑制（過去の成功体験からの脱却）」という高度な認知負荷をパズルメカニクスとして統合している。

## 1. プロジェクト概要・コンセプト

### 1.1 背景と目的

人間の前頭前野（Prefrontal Cortex）は、状況の変化に合わせて自らの行動方針や思考の枠組みを柔軟に切り替える**「認知的柔軟性（Cognitive Flexibility / セットシフティング）」**を司っている。神経心理学における代表的検査である**ウィスコンシン・カード分類課題（WCST）**では、被験者に分類ルール（色・形・数など）を一切教えず、試行錯誤の結果（正解/不正解のフィードバックのみ）からルールを帰納推理させ、途中でルールを予告なく変更した際に「古いルールに執着してしまうエラー（**保続エラー: Perseverative Error**）」を測定する。

本作『Rule Shifter』は、このWCSTの検査原理を「一筆書きグリッド迷路」に完全統合。プレイヤーは4次元属性（色・形・数・模様）を持つトークンが並ぶ迷宮を探索するが、**「どの属性が隣接移動の接続キーになっているか」は一切明かされない**。プレイヤーは最小限の試行（Pass/Reject）から現在支配的なルールをアブダクション（仮説推論）し、さらに迷宮途中で突如発生する「ルールのサイレント急変（相転移）」に適応して古い成功体験を即座に破棄しながらゴールを目指す。

### 1.2 コアバリュー

1. **ブラックボックス接続（Black Box Deduction）**: 移動ルールは画面に表示されない。隣接マスを踏んだ瞬間の「Pass（和音と光）」と「Reject（鈍いバズと弾き）」のバイナリフィードバックのみから隠された法則を演繹・帰納する快感。
2. **4次元属性シンボル空間**: 各マスが「色（4色）」「形状（4種）」「個数（1〜4個）」「テクスチャ（4種）」の独立した4次元属性を保持。4×4×4×4＝256通りの膨大な属性組み合わせによる高度な視覚・概念干渉。
3. **サイレント相転移（Silent Phase Shift）**: シフターノード通過または歩数経過により、有効ルールが予告なく別の属性次元へ急変。直前まで有効だった移動法則が突如Rejectされることで、前頭葉のギアチェンジを強制。
4. **保続エラー測定とFlexibility Index（柔軟性スコア）**: ルール急変後に「直前まで正しかった旧ルール」を何回試してしまったかをリアルタイム追跡。自身の思考の固執度合いを客観的に可視化。
5. **仮説メモトグル（Hypothesis Scratchpad）**: 初心者・中級者がワーキングメモリの過負荷で挫折しないよう、消去法で候補属性を除外・固定できる直感的な推論HUD（高さ固定バー・44pxタップ領域）を提供。
6. **4×4ファインダー × 均一視認性アーキテクチャ**: 『Stroop Route』で確立したスマホ最適化アーキテクチャ（CSS Container Query `100cqw` 基準、4×4ファインダー＋3マススライド＋3×3ミニドットピクト）を踏襲し、最大10×10の大迷宮でもセルサイズと視認性を完全均一に維持。
7. **デイリー・ブラインド・チャレンジ ＆ SNS共有**: 毎日日替わりで全世界共通のシード盤面を配信。「保続エラー最少回数」「最短手数」をWordle風絵文字でSNSにシェア可能。

## 3. ゲームルール・パズルメカニクス詳細仕様

### 3.1 4次元属性空間の定義とSVGトークン視認性設計

盤面上のすべてのセルは、独立した4つの属性次元を持つトークンとして定義される。

```text
Cell Attribute Tuple = (Color, Shape, Count, Texture)
Total States = 4 (Colors) × 4 (Shapes) × 4 (Counts) × 4 (Textures) = 256 Unique Variations
```

| 次元 (Dimension) | ID | 属性値 0 | 属性値 1 | 属性値 2 | 属性値 3 | 視覚表現仕様 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **1. 色 (Color)** | `color` | `CYAN` (#06b6d4) | `AMBER` (#f59e0b) | `EMERALD` (#10b981) | `MAGENTA` (#d946ef) | トークン塗色および外周リングの発光色 |
| **2. 形状 (Shape)** | `shape` | `CIRCLE` (円) | `SQUARE` (正方形) | `TRIANGLE` (正三角形) | `DIAMOND` (菱形) | セル中央に描画される幾何学シンボルの外形 |
| **3. 個数 (Count)** | `count` | `1` (1個) | `2` (2個) | `3` (3個) | `4` (4個) | 描画される幾何学シンボルの個数（対称配置） |
| **4. 模様 (Texture)**| `texture`| `SOLID` (べた塗り) | `STRIPE` (45°斜線) | `DOTS` (水玉ドット) | `GRID` (微細格子) | シンボル内部のSVGパターンテクスチャ |

#### 4次元トークン視認性（LOD: Level of Detail）ガイドライン
スマートフォン小画面での視認性を担保するため、以下の描画パラメータを厳守する：
1. **外形ストローク太さ**: 各シンボルの輪郭線は最低 `stroke-width: 2.5px〜3px` を確保。暗黒背景上でくっきりと形状が識別できるようにする。
2. **個数に応じたパターンスケーリング（LOD）**:
   * **個数 1個**（シンボル直径 約48px）: ストライプ間隔 6px、ドット径 3px、グリッド間隔 6px。
   * **個数 2個**（シンボル直径 約32px）: ストライプ間隔 7px、ドット径 3.5px、グリッド間隔 7px。
   * **個数 3個**（シンボル直径 約26px）: ストライプ間隔 8px、ドット径 4px、グリッド間隔 8px。
   * **個数 4個**（シンボル直径 約22px）: 密集による潰れを防ぐため、ストライプ本数を2〜3本に間引き、ドット径を拡大（4.5px）。

### 3.2 パズルクリアの終了条件

* **クリア条件**: **「スタートマスから出発し、自己交差せずに現在の潜伏ルールを満たしながらゴールマスへ到達すること（Pathfinding / 経路探索）」**。
* **非Hamiltonian Path**: 盤面上の全マスを踏破する必要はない。スタートからゴールへの合法な経路が1本でも成立した瞬間にクリアとなる。
* 盤面上の未使用マスは「妨害セル（Distractor）」として機能し、偶発的な別属性の一致によってプレイヤーの仮説を惑わせる。

### 3.3 移動制約とブラックボックス判定タイミング

プレイヤーは現在パスの先端（Tip）から隣接するマスを選択して経路を伸ばす。

1. **直交隣接移動**: 上下左右の4方向（Manhattan距離 = 1）にのみ移動可能。斜め移動は不可。
2. **自己交差禁止（一筆書き）**: すでに現在のパスに含まれているマスへの再進入は禁止（Undoによる取り消しを除く）。
3. **ブラックボックス判定（Pass / Reject）**:
   * プレイヤーが先端に隣接するマスをタップまたはドラッグ侵入した瞬間、内部エンジンが「直前マス」と「移動先マス」を現在のアクティブな潜伏ルール（`activeRule`）と照合する。
   * **Pass（合致）**:
     * パス配列およびルール履歴にターゲットセルを追加（`path.push(targetCell)`, `ruleHistory.push(activeRule)`）。
     * 軽快なペンタトニック和音チャイム（0.12s）を再生し、SVG接続ラインを滑らかに伸長。
     * 直前の「連続拒否カウント」をリセット。
   * **Reject（不合致）**:
     * パスは前進しない（手数は進まない）。
     * ターゲットセルが一瞬赤色にフラッシュし、微細に振動（`animate-shake`）。
     * 鈍い低音エラーバズ（sawtooth 120Hz➔70Hz）を再生。
     * 後述の「保続エラー（Perseverative Error）」判定ロジックを実行。

### 3.4 潜伏適合ルール体系 (Hidden Connection Rules)

ゲーム内でアクティブになる潜伏ルールは以下の4種（基本）＋2種（上級）とする。常にこのうちの**1つのみ**が「正解の接続ルール」として密かに有効化されている。

| ルールID | 対象次元 | 接続成立条件 (Pass Condition) | プレイヤーの推理視点 |
| :--- | :--- | :--- | :--- |
| `MATCH_COLOR` | 色 (`color`) | $\text{Target.color} == \text{Prev.color}$ | 「形や数はバラバラだが、同じ色のマスだけ進める！」 |
| `MATCH_SHAPE` | 形状 (`shape`) | $\text{Target.shape} == \text{Prev.shape}$ | 「色や模様は違っても、同じ図形（三角なら三角）なら繋がる！」 |
| `MATCH_COUNT` | 個数 (`count`) | $\text{Target.count} == \text{Prev.count}$ | 「図形の種類に関係なく、個数が一致するマス同士だけ通れる！」 |
| `MATCH_TEXTURE`| 模様 (`texture`)| $\text{Target.texture} == \text{Prev.texture}$ | 「縞模様なら縞模様、ドットならドット同士だけが接続可能！」 |
| `DELTA_COUNT` *(上級)* | 個数差分 | $\|\text{Target.count} - \text{Prev.count}\| == 1$ | 「個数が1個増えるか1個減るマスへ階段状にステップ！」 |
| `ALL_DIFF` *(超上級)* | 全次元相異 | 全4属性が直前セルとすべて不一致 | 「色も形も数も模様も、何ひとつ被らないマスだけが進路！」 |

### 3.5 相転移（ルール急変・シフターノード）メカニクスと保続エラートースト

本ゲーム最大の特徴であり、前頭葉のセットシフティング能力を試す中核システム。

1. **相転移のトリガー方式**:
   * **方式A: シフターノード（🌀 Shifter Node）踏破**: 盤面上の特定セル（二重の回転波紋アイコン 🌀 を持つマス）を踏んだ瞬間に発動。
   * **方式B: ステップ数トリガー（サイレント相転移）**: 高難易度ステージでは、例えば「5手進むごとに予告なくルールが自動急変」する。
2. **相転移の実行シーケンス**:
   * 現在の `activeRule` を除外した残りのルールプールから、新しいルールを決定（例：`MATCH_SHAPE` ➔ `MATCH_COUNT`）。
   * 直前の旧ルールを `previousRule` に保存。
   * 画面全体に一瞬だけ淡い紫色の空間歪みエフェクト（シマーグロー）が走り、神秘的なフェーズシフト音（アルペジオシマー）が鳴動。
3. **保続エラー（Perseverative Error）の厳密定義と瞬間トースト演出**:
   * 相転移が発生した直後、プレイヤーが**「直前まで有効だった旧ルールを満たすが、新ルールには適合しないマス」**へ移動を試みてRejectされた場合、これを**「保続エラー（Perseverative Error）」**としてカウントする。
   * **演出（『Stroop Route』準拠）**:
     * 画面盤面上部に、瞬間トースト（フローティング警告バッジ）がポップアップ：
       `[ ⚠️ 旧ルールへの固執！（保続エラー） ]`
       （ローズ/パープルネオン背景、`AlertCircle` アイコン付き、`animate-shake` + `animate-fade-in`）
     * 自身の思考の固執を直感的に自覚させ、セットシフティングを促す。

### 3.6 Undo（1手戻す）・リセット・手詰まり仕様

1. **Undo（1手戻す）とルール復元スタック**:
   * **トリガー**: UI上の「1手戻す」ボタン押下、直前のセル（先端の1つ手前）をタップ、キーボードの `Z` キー / `BackSpace` キー。
   * **ルール復元挙動**: パス先端（`path.pop()`）と同時に、各歩数ごとのルール履歴スタック（`ruleHistory.pop()`）を取り出す。シフターノードを跨いで巻き戻った場合は、ルール状態も過去の該当ルールへ正確に復元される。
   * **推理知識の保持**: Undoを行っても、プレイヤーが手元の「仮説メモ」に記録したメモ内容は消去されない。
2. **リセット**:
   * **トリガー**: UI上の「リセット」ボタン押下、または `R` キー。
   * **挙動**: パスを初期位置（スタートマスのみ）に戻し、ルールを初期ルールにリセット。タイマーは継続。
3. **手詰まり（Dead End）検出と案内**:
   * **検知条件**: 先端から上下左右の4マスについて、(1) 盤外、(2) 訪問済み、(3) 現在ルール不適合 により進める合法マスが **0個** になった瞬間。
   * **演出・UI案内**: 先端セルが小刻みにシェイクし、ステータスバーに「進路がありません。1手戻す（Undo）か別ルートを試してください」と警告表示。「1手戻す」ボタンがパルス点滅。

### 3.7 仮説メモトグル（Hypothesis Scratchpad）詳細仕様

盤面直下に、プレイヤーが頭の中で立てた仮説を外在化できる4つのトグルボタンを常設する。

```text
+-------------------------------------------------------------+
|  🎨 色 [ ? ]  |  🔷 形 [ ✓ ]  |  🔢 数 [ × ]  |  ▦ 模様 [ × ] |
+-------------------------------------------------------------+
```

* **UI配置・寸法**:
  * 高さ固定バー（`h-12` / 48px）として盤面直下に配置。
  * 各ボタンは **44px × 44px 以上のタップ領域** を確保し、誤タップを防止。
* **フォントサイズ・配色**:
  * 属性名ラベル: **`text-xs sm:text-sm font-black`**
  * ステータス印: **`text-sm sm:text-base font-black`**
  * ステータス状態色:
    * `?`（未定 / UNKNOWN）: スレート（`text-slate-400 bg-slate-800/60`）
    * `✓`（有力 / CANDIDATE）: エメラルドネオン（`text-emerald-300 bg-emerald-950/80 border-emerald-400 shadow-[0_0_8px_rgba(16,185,129,0.5)]`）
    * `×`（棄却 / ELIMINATED）: ローズネオン（`text-rose-400 bg-rose-950/80 border-rose-500/80`）
* **アシストモード（初級者設定）**:
  * アシストON時、隣接マスでRejectが発生した際、そのマスと直前マスで一致していた属性（＝正解ルールではあり得ない属性）をシステムが自動で「×（棄却）」にマーク。

### 4.1 盤面スケール基準と表示仕様

全ステージにおいて、画面内に見えるセルサイズを**「横幅の約1/4」**で完全均一化する。

### 4.4 操作系（タッチ・マウス・キーボード）の統合仕様

1. **タッチスクリーン（スマホ）**:
   * 先端セルからのドラッグ、または隣接有効セルのタップで前進。
   * 先端以外でのスワイプで視界カメラをスライド移動。
   * 先端がファインダー端に到達した際の自動カメラ追従。
2. **PCマウス操作**:
   * クリックで1歩進める、直前セルクリックでUndo。
   * ドラッグ押し下げ移動（`pointerenter` による連続接続）。
3. **PCキーボード操作**:
   * カーソルキー（`↑` `↓` `←` `→`） / `W` `A` `S` `D`: 4方向への前進試行（戻るキーはUndo）。

   * `1`〜`4` キー: 仮説メモトグル（色・形・数・模様）のショートカット切替。
   * `H` キー: AIヒント（現在のルールに合致する合法隣接マスを1箇所パルス表示）。

### 4.5 設定・アクセシビリティ（CUDモード）

1. **カラーユニバーサルデザイン（CUD）モード**:
   * **OFF（デフォルト）**: トークン塗色とネオングローで色を表現。
   * **ON**: 各マスの右下に微小な色識別バッジ（C:シアン、A:アンバー、E:エメラルド、M:マゼンタ）を付与し、色覚多様性を持つプレイヤーの判別を完全保証。
2. **触覚フィードバック（Haptics API）**:
   * 対応モバイル端末において、Pass時は微小な心地よい振動（15ms）、Reject時は重いエラー振動（40ms + 40ms）を発生。

## 7. AI自動問題生成・解到達性保証アルゴリズム

### 7.1 生成パイプライン

1. **基準パス生成フェーズ**:
   * スタート $(0, 0)$ からゴール $(\text{size}-1, \text{size}-1)$ へ向けて、自己交差のない長さ $L$ の経路を重み付きランダムウォークで生成。
2. **相転移ノード配置・ルール分割フェーズ**:
   * パスの中間地点（1箇所または2箇所）に `SHIFTER` セルを配置し、経路を「セグメント1」「セグメント2」に分割。
   * 各セグメントに対し、重複しない潜伏ルール $R_1, R_2$（例：$R_1=\text{MATCH\_COLOR}, R_2=\text{MATCH\_SHAPE}$）を割り当てる。
3. **4次元属性逆算割り当てフェーズ**:
   * パスの始点にランダムな4次元タプル $(c_0, s_0, n_0, t_0)$ を付与。
   * 各セグメントのルール制約を満たすよう、パスに沿って順次隣接セルの属性を確定。
   * **干渉最大化**: 有効ルール以外の3次元属性は可能な限り変化させ、特定を難しくする（例：色一致ルール区間では、形状・個数・テクスチャを毎手ランダムに変更する）。
4. **妨害セル（Distractor）充填と短絡防止フェーズ**:
   * 空きマスにランダムな4次元トークンを充填。
   * パス外への意図しない短絡（ショートカット）が多発して推理のステップが形骸化しないよう、隣接マスへの適合確率を調整。

### 7.2 解法保証と「別解」の許容方針

* **到達性保証**: 基準パスにより、少なくとも1つの合法解が存在することを100%保証。
* **別解の許容（No Unique Solution Restriction）**:
  * プレイヤーが意図された基準パスとは異なる別ルートを発見し、かつ各セグメントの潜伏ルールに適合してゴールに到達した場合も完全なクリアとして認定する。

### 7.3 デイリーチャレンジ仕様

* 日付シード（例：`20261028`）を基に Mulberry32 擬似乱数生成器を初期化。
* 全世界共通のシード盤面が毎朝自動生成され、保続エラー回数とクリアタイムをランキング形式で比較可能。

   * `.labyrinth-frame` による単一外枠、3マススライドカメラ、タッチスワイプ／PCマウス／キーボード操作（↑↓←→, WASD, 1-4, Z, R）の実装。
5. **Phase 5: AI問題自動生成・デイリーチャレンジ・SNS共有の実装**
   * バックトラッキング自動生成、Mulberry32によるデイリーシード配信、Flexibility Indexスコアリング、Wordle風SNS共有モーダルの実装。
   * **常時表示ステータスを「総ミス数」へ統一改修（案Cの採用）**:
     * ヘッダーの第3ステータス表示を、プレイヤーにとって直感的な「総ミス数（`totalRejects`）」に変更（アイコンを警告・ミスの `AlertCircle` に刷新）。不合致マスを踏むたびに即座にカウントが 0 ➔ 1 ➔ 2 と更新され、フィードバックの確実性を向上。
     * 神経心理学的な「保続エラー（旧ルールへの固執）」はクリアモーダル（`ClearModal`）および Flexibility Index 評価の内訳として「うち保続: X回」と明示する構成に整理。
   * **2要素一致ルールの近接干渉セル（Near-Miss Distractor）高度化**:
     * 2要素同時一致ルールにおいて、周囲のダミー候補マスを「片方の要素だけ一致させ、もう片方は不一致」となるよう意図的に生成。1要素だけ見て判断する直感をトラップにかけ、2属性をワーキングメモリ上で同時に照合・検証しなければ正解を見出せない高難度な認知負荷を実現。
     * ショートカット防止検証（`validateConnection`）により、近接干渉セルが隣接する他のパスセルと不正に接続して別解や近道が生じないことを保証。
   * **正解ルートの直線抑制＆迷宮屈曲アルゴリズム（Zigzag Prioritization）**:
     * `findRandomPath` において、同方向への連続直進を最大2マスに制限。直角方向（垂直方向）への旋回を75%の確率で優先探索し、直線の単調な回廊を排除。盤面全体を縦横に蛇行・旋回する本格的な迷宮パスを生成。
   * **ステージ説明文の省略解消**: `StageSelectModal` の `line-clamp-1` / `truncate` を撤廃し、全ステージの説明文を折り返し全文表示に改修。モーダル幅を `max-w-md` に最適化。
